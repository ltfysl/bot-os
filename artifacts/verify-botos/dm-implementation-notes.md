# DM Implementation Notes

## Overview

This PR implements 1:1 Direct Message (DM) threads for bot-to-bot communication on the main process bus. This enables two agents to open/reuse a private DM channel, exchange messages, and wake each other using the existing wake infrastructure.

## Architecture Design

### DmManager (src/main/dms.ts)

A dedicated `DmManager` class has been created alongside `RoomManager` to handle DM-specific logic. This keeps DMs architecturally distinct from multi-member rooms rather than treating them as a special case of rooms with 2 members.

**Key Design Decisions:**

1. **Canonical Pair Uniqueness**: DM IDs are generated by sorting the two agent IDs alphabetically and concatenating them with a prefix (`dm-{agentId1}-{agentId2}`). This ensures that:
   - DM between agents A and B is the same as DM between B and A
   - `getOrCreateDm(A, B)` and `getOrCreateDm(B, A)` return the same DM instance
   - No duplicate DM threads can exist for the same pair

2. **Persistence**: DMs are persisted to `userData/dms/` directory:
   - `dms.json`: List of all DM threads with participants and metadata
   - `messages.json`: All messages organized by DM ID
   - Mirrors the pattern used by RoomManager for consistency

3. **Self-DM Prevention**: The system explicitly prevents creating a DM with oneself (throws error if agentId1 === agentId2)

### Integration with AgentBus

The existing wake infrastructure has been extended to support DM context:

1. **Wake Events Extended**: 
   - `WakeFailureEvent` and `WakeTimeoutEvent` now include optional `dmId` field
   - This allows wake errors to be attributed to either rooms OR DMs
   - Events maintain backward compatibility (dmId is optional)

2. **Wake Path**:
   - `AgentBus.requestAgentWake()` now accepts optional `dmId` parameter
   - Wake failures/timeouts in DM context include dmId in event payload
   - Uses the same timeout (5000ms) and error handling as room wakes

3. **No Room Membership Checks for DMs**:
   - DM wakes skip the room membership validation logic
   - Only validates that both participants exist in the DM
   - Simpler validation path than rooms

## IPC Layer (Secret-Safe)

### Preload Types (src/main/preload.ts)

New types exposed to renderer:
```typescript
interface DirectMessage {
  id: string;

  createdAt: number;

interface DmMessage {

}

interface DmStreamChunk {
  id: string;

  senderAvatar: string;
  chunk: string;
  done: boolean;
}
```

### IPC Handlers (src/main/main.ts)

**Read Operations:**
- `get-or-create-dm`: Creates or retrieves existing DM for two agents (idempotent)
- `get-dm`: Retrieves existing DM without creating
- `list-dms-for-agent`: Lists all DMs for a given agent
- `get-dm-messages`: Retrieves message history for a DM

**Write Operations:**
- `send-dm-message`: Sends message with optional wake
- `send-dm-message-stream`: Sends message with streaming response and optional wake

**Event Channels:**
- `dm-stream-chunk`: Streaming message chunks from DM responses
- `dm-wake-response`: Complete wake response from target agent
- `wake-timeout`: Wake timeout events (includes dmId when from DM)
- `wake-failure`: Wake failure events (includes dmId when from DM)

## Secret Safety

**No API Keys in IPC Payloads:**
- All wake events (timeout, failure, membership-denied) only contain:
  - Agent IDs (public identifiers)
  - DM/Room IDs (public identifiers)
  - Error messages (sanitized, no provider secrets)
  - Timestamps
- Provider secrets remain in main process only
- Message content does not include provider API keys
- Streaming chunks are provider responses only (no internal auth data)

**Verification:**
- Reviewed all `event.sender.send()` calls for DM functionality
- Confirmed no provider secret leakage in wake event payloads
- Wake errors use reason codes ('timeout', 'agent-not-found', etc.) not raw errors

## Wake Path Details

### Bot-Initiated Wake in DM

When `shouldWake=true` in `send-dm-message` or `send-dm-message-stream`:

1. **Validate DM membership**: Verify sender is a participant
2. **Identify target**: Get other participant from DM
3. **Request wake**: Call `agentBus.requestAgentWake(senderId, targetId, message, undefined, dmId)`
4. **Execute provider call**: Send message through target agent's provider
5. **Handle response**: 
   - For non-streaming: emit `dm-wake-response` event
   - For streaming: emit `dm-stream-chunk` events as they arrive
6. **Persist message**: Save assistant response to DM messages

### Wake Failure Handling

Wake failures in DM context follow the same path as room wakes:

- **Timeout (5000ms)**: Emits `wake-timeout` event with dmId
- **Agent not found**: Emits `wake-failure` with reason='agent-not-found' and dmId
- **Provider not found**: Emits `wake-failure` with reason='provider-not-found' and dmId
- **Provider unavailable**: Emits `wake-failure` with reason='provider-unavailable' and dmId
- **General error**: Emits `wake-failure` with reason='general-error' and dmId

All wake events include:
- `dmId`: DM identifier (when wake was DM-initiated)
- `initiatorAgentId`: Agent that initiated the wake
- `targetAgentId`: Agent that failed to wake
- `reason` or `timeoutMs`: Specific failure reason
- `errorMessage`: Human-readable error (secret-safe)
- `timestamp`: Event timestamp

### Runtime Testing (Manual)

Since this PR scopes to IPC + preload types only (no UI chrome), manual testing requires:

1. **Start app**: `npm start`
2. **Open DevTools console**
3. **Test DM creation**:
   ```javascript
   await window.electronAPI.getOrCreateDm('1', '2')
   // Should return: { id: 'dm-1-2', participants: ['1', '2'], createdAt: <timestamp> }
   ```

4. **Test idempotency**:
   ```javascript
   const dm1 = await window.electronAPI.getOrCreateDm('1', '2')
   const dm2 = await window.electronAPI.getOrCreateDm('2', '1')
   console.log(dm1.id === dm2.id) // Should be true
   ```

5. **Test DM listing**:
   ```javascript
   await window.electronAPI.listDmsForAgent('1')
   // Should include the dm-1-2 we just created
   ```

6. **Test message send**:
   ```javascript
   const dm = await window.electronAPI.getOrCreateDm('1', '2')
   await window.electronAPI.sendDmMessage(dm.id, 'Hello from agent 1', '1', false)
   const messages = await window.electronAPI.getDmMessages(dm.id)
   console.log(messages) // Should show user message
   ```

7. **Test wake**:
   ```javascript
   const dm = await window.electronAPI.getOrCreateDm('1', '2')
   
   // Set up wake response listener
   window.electronAPI.onDmWakeResponse((msg) => {
     console.log('Wake response:', msg)
   })
   
   // Send with wake
   await window.electronAPI.sendDmMessage(dm.id, 'Wake up!', '1', true)
   // Should see agent 2's response in wake response listener
   ```

8. **Test wake failure handling**:
   ```javascript
   // Set up wake failure listener
   window.electronAPI.onWakeFailure((event) => {
     console.log('Wake failed:', event)
   })
   
   // Try to wake non-existent agent
   const dm = await window.electronAPI.getOrCreateDm('1', '999')
   await window.electronAPI.sendDmMessage(dm.id, 'Hello', '1', true)
   // Should emit wake-failure event with reason='agent-not-found'
   ```
